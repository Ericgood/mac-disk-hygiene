# 06 防止无序扩张的规则

清一次不难，难的是不让它再长回去。下面这些规则可以直接写进各个 AI 编程助手都会读的全局指令里（如 `~/.claude/rules/…`、`~/AGENTS.md`），让所有会话遵守同一份。可直接复制的版本见 [`templates/agent-disk-rules.md`](../templates/agent-disk-rules.md)。

## 1. worktree：谁开谁收

- 每个仓库同时最多 **3 个**活跃 worktree；要开第 4 个，先收掉已合并 / 已放弃的。
- 任务合并或放弃后，**开它的会话**用 `git worktree remove` 收掉；有未提交改动或独有提交时不收，告诉用户。
- 不用 `rm -rf`、不用 `--force`。

## 2. 依赖：能不装就不装

- 只改文档、配置、文案的 worktree，**不跑** `npm install` / `pnpm install` / `pip install`。
- 需要依赖时优先复用主仓库已装好的；JS 项目新装优先 pnpm（全局内容寻址存储，多个副本不重复占空间）。

## 3. 构建产物：只留最新 3 个

- `dist/` 等安装包目录，每个只保留最新 3 个包及对应 mapping；打新包后顺手删本会话产生的最旧包。
- 长期保留的发版包放 NAS 或 Release，不堆本机。
- Rust 项目调试时复用同一个 `target`，阶段结束 `cargo clean --profile dev`。

## 4. 临时文件与日志

- 放项目内 `.localtmp/`（加进 `.gitignore`），单项目不超过 500 MB，任务结束清掉本次产生的。
- 不在 `~` 根目录、`~/.local/share` 随手新建目录；确实需要时先说明用途和预计大小。
- 新项目放进分类目录，不在 `~` 下平铺。

## 5. 后台进程（直接影响 swap）

- Android 构建同一时间只跑一套；构建完 `./gradlew --stop`，或在 `gradle.properties` 设置 `org.gradle.daemon.idletimeout`。
- 不留长期闲置的 dev server、watcher、模拟器进程；任务结束关掉本会话启动的。
- 同时活跃的 AI 会话控制在必要数量，闲置的归档。

## 6. 长对话按阶段换新

- 一个对话只做一件事。阶段做完，或对话已经很长（频繁压缩上下文、变慢），就换新对话。
- 换之前把交接写进项目文档：目标、进度、下一步、踩过的坑、相关分支 / worktree / 构建产物、等用户决定的事。
- 旧对话不删，归档即可；多数 AI 编程 App 会自动压缩空闲对话的记录，体积能降一个数量级。

## 7. 收尾自查

每个任务结束前花 10 秒检查：本次是否新开了 worktree、装了依赖、产生了 >500 MB 的文件？有就按上面收掉，并在汇报里写一行「本次新增占用：xx」。

## 8. 硬保护清单

清理规则必须分两层：**硬保护**（永远生效）和**可调白名单**分开写，避免改白名单时把关键保护丢掉。硬保护至少包括：

- 浏览器个人资料目录和缓存目录（只能通过浏览器自己的入口清，见 [03](03-chrome.md)）；
- 代理 / 网络工具的配置；
- AI 编程工具的配置、会话记录、认证文件；
- 各 App 登录态、钥匙串；
- 本地编译依赖的模拟器运行时；
- 正在开发的源码和未提交改动。
